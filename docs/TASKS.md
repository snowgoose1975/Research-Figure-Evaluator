# 模型派工卡与长跑协议

所有任务先读根目录 `AGENTS.md`。本文件区分“有权定义标准”和“按标准积量执行”，不把写代码都叫体力活。

## 1. 模型资源分配

| ID | 性质 | 推荐资源 | 首件交付 | 可持续积量的部分 |
|---|---|---|---|---|
| T00 | **脑力** | 玉米选择的强推理/编码模型 | 冻结架构、schema、信息隔离、绘图映射、读图 prompt、共享 fixture | 初始化和类型落地可再委派，但定义权不下放 |
| T04 | **脑力** | 强推理模型，优先保证判断质量 | 原子意图、实体对齐、错误分类、标注规则、golden 判例 | 固定规则编码/测试可委派，匹配口径不下放 |
| T06 | **脑力** | 强编码/审查模型，可与 T00 同一个 | 可运行集成、边界审查、阶段归因、候选版结论 | 跑命令和整理证据可交 T07 |
| T01 | **体力执行，脑力审查** | 常规模型，按冻结方案实现 | A/B 调用及隔离 fixture 通过 | 错误分支、适配器、记录、受控运行 |
| T02 | **体力执行，脑力审查** | 常规模型，能看渲染结果 | 一份手写记忆忠实变成 SVG/PNG | 多种固定符号、遮挡修复、布局覆盖 |
| T03 | **体力** | 常规前端模型 | fixture 驱动的完整用户路径 | 全部状态、响应式、可访问性、导出体验 |
| T05 | **体力执行，真值需脑力审核** | 可持续制图/整理的模型 | 1 对自绘图与逐项标注 | 按已审定语义配方扩到 3 对/6 对、元数据 |
| T07 | **体力执行，结论需脑力审核** | 长跑执行模型 | 有限批次计划与首批可追溯记录 | 批量运行、失败汇总、报告、截图、材料草稿 |

“强模型”由玉米按实际可用模型选择，本总纲不替玉米假定型号。普通模型若也能稳定完成任务即可使用；架构、评价和最终审查不能因为便宜或长时间运行就降低验收标准。

## 2. 执行顺序

```text
阶段 A：T00-D 架构设计  ||  T04-D 评价/标注规则设计
                     ↓ 共同对齐并冻结 G0
阶段 B：T00 工程与公共类型落地
         ↓               ↓                 ↓
       T01 模型         T02 绘图          T03 页面
       T04-E 评价实现    T05 样例（按批准配方）
                     ↓
阶段 C：T06 集成 + T07 有限批次验证
                     ↓
阶段 D：强模型审查结论，T07 整理材料，玉米授权后提交
```

T04-D 只产规则和 golden 判例，**不依赖 T00 先写完代码**；T00-D 也不等待完整 evaluator。两者先对齐定义，消除循环等待。T03 可以提前草拟静态信息层级，但不在合同未定时造 API。

只有两三个执行模型时，同一模型可依次承担多个角色；T00 与 T06 通常复用，保留总指挥上下文。不同模型不要同时编辑同一文件。

## 3. 通用可复制前缀

将这段与相应任务卡一起交给模型：

> 你在 Research-Figure-Evaluator 项目工作。先读 AGENTS.md、docs/MASTER_PLAN.md、docs/CONTRACTS.md、docs/VALIDATION.md 和 docs/TASKS.md 中本任务卡。只改任务拥有的路径。先核实前置产物是否真实存在，再实施；不要只回答计划。遵守玉米红线，不删除、不改 .env/密钥/CI/CD、不 push、不安装全局依赖、不公开发布。接口或科学语义有歧义时提交证据给脑力负责人，继续不受影响的工作。完成后写 docs/handoffs/对应任务.md，附实际验证命令、结果、限制和待办。mock、真实运行和回放必须明确区分。

## 4. T00：架构与共享基础

**性质：脑力；定义错误会传播全项目，优先分配强模型。**

前置：玉米确认总纲/明确派发此卡。与 T04-D 并行，先完成设计对齐再冻结公共类型。

拥有：`docs/CONTRACTS.md`、`src/lib/schemas/`、`src/lib/prompts/`、`data/fixtures/contracts/`、`tests/contracts/`、根工程配置/依赖清单/锁文件及最小 shell。后续将根配置、pipeline/storage/API 的所有权交 T06。

决策：模块边界、状态机、数据容量、输入投影、renderer 语义表、prompt 的可见信息/不确定处理、隐私与日志字段、依赖兼容性。T04 决定评价与标注口径，双方对 AtomicClaim/报告字段共同确认。

交付：

- 先列不超过一页的关键决策和风险，更新合同；按官方资料核对所选模型接口、Next.js、Zod、布局/PNG 组件的当前兼容性，冻结项目局部版本。
- 落地最小工程和 schema；建立至少一套共享输入/A记忆/渲染期望/B理解/报告 fixture，其中明确哪些是手写预期。
- 固定 A/B 提示词和版本；不把关键点、样例答案、文件名、旧上下文送给 readers。不要求隐藏思维链。
- 验证 Windows/Node 的 SVG→PNG 与持久进程运行方式。普通托管不满足本地持久化时，记录约束，不私自增加数据库或部署。
- 配置必要 npm scripts 和忽略规则；核对空本地仓库与远端关联。不要 push；若任何操作触及用户红线先交玉米。

验收：公共 schema 接受合法 fixture、拒绝悬空引用/非法 bbox/重复 ID/容量超限；初始化检查通过；T01–T05 能引用同一套类型。

可复制指令：

> 执行 T00。你拥有底层架构与公共合同，先与 T04 的评价/标注定义对齐，完成 G0 再落地共享类型、fixture 和最小工程。不要扩大产品范围。将体力实现者无权修改的语义、prompt 边界和错误处理写成可检查规则。最后列出各任务已具备/未具备的开工条件，不用“骨架完成”代替真实验证。

## 5. T04：评价、标注规则与 evaluator

**性质：脑力；判断是否正确比代码量更重要。**

拥有：`src/lib/evaluation/`、`tests/evaluation/`、`data/fixtures/evaluation/`、`docs/annotation-guide.md`。新建标注指南已在此约定：只放标注规则/例子/审核状态，不混入 holdout 结果。共享类型/合同变动交 T00，不直接争抢文件。

T04-D：在完整工程之前，给出原子关键点定义、required_fields、实体对齐/同义词规则、不确定口径、绘图/阅读损失划分、样例配方和开发/保留划分规则。用 8–12 个人工 golden 判例覆盖方向、抑制/促进、条件范围、证据状态、同义词歧义与新增断言。

T04-E：G0 后按规则实现 `normalizeIntents`、`evaluate`、`compareRuns` 及 direct-check 结果解析；语义模型仅辅助无法规则处理的表述，保留理由并标复核，不强制判正确。

验收：

- 抑制不能被“影响”算完整保留；条件和假说不能因实体相同被忽略。
- A/B 的同名局部 ID 不自动对齐；别名有歧义时 uncertain。
- 不将非 K 内容算幻觉；不把 API/JSON 失败算信息遗漏。
- 同配置改图可对比；改了 K/模型/prompt 等须显式提示不可直接对比。
- 完整保留数、分母、不确定数和新增未匹配项均可追溯。

可复制指令：

> 执行 T04，先做 T04-D 再做 T04-E。你负责评价是否可信，不为提高通过率放宽语义匹配。先交能约束 schema 和样例生产的规则及 golden 判例，与 T00 对齐。随后实现评价模块并验证。作者意图若模糊就要求结构化确认或判不确定，不替作者编标准答案。交付同时注明哪些结论可自动化、哪些必须复核。

## 6. T01：模型适配器与独立读图

**性质：按冻结方案的体力执行；隔离设计和 prompt 变更必须脑力审查。**

前置：G0、共享 schema、冻结 prompt；可先用 mock 验证，真实调用依赖模型权限和已获准的配置。

拥有：`src/lib/model/`、`tests/model/`。不修改 `src/lib/prompts/`、schema、锁文件和 `.env`；依赖需求列给 T00/T06。

交付：单 provider adapter、A/B 独立调用、结构化解析、暂时错误有限重试、用量记录、独立 direct-check。每个 reader 请求只拿白名单字段。SDK key 仅服务端读取，不输出其值。

验收：用捕获请求的 adapter 验证 A 不含 K、B 仅有重建 PNG；两次调用无共享聊天历史；解析失败不会返回空图冒充有效；服务报错不回退 mock。首件通过后再补错误矩阵与真实 smoke。

升级触发：需要改 prompt、模型不支持合同、无法隔离 SDK 会话、结构化 schema 与 API 不兼容；不得自行删字段。

可复制指令：

> 执行 T01。按冻结合同实现模型适配器、A/B 独立请求和 direct-check，优先证明实际请求的信息边界。先跑 fixture 与捕获请求测试，再在已有权限下做最小真实调用。没有密钥就交付准确的未验证状态，继续错误分支和日志实现；不要写 .env、打印 token 或造真实输出。不要改 prompt 和评价定义。

## 7. T02：受控重建绘图

**性质：语义表冻结后的体力执行；符号语义和审计结论由强模型审查。**

前置：G0、RenderInput/Artifact、语义映射表、手写正控。

拥有：`src/lib/reconstruction/`、`tests/reconstruction/`、`data/fixtures/reconstruction/`。图形方案需要新增依赖时交 T00/T06 统一处理。

交付：纯投影函数、自动布局、固定 SVG、PNG 转换、渲染条目审计；条件/证据/不确定文字可见。用户输入图不作为布局参考。所有合法输入都有明确结果或不支持说明。

验收：每种映射至少一份正控；视觉检查文字未裁切、抑制 T 端点可见、方向可分、条件有明确目标、分组/图例未丢。unsupported 不标结构 complete；结构审计与 PNG 视觉审查分别记录。B 获取 PNG 后看不到局部 ID、bbox 和 A 笔记。

升级触发：某字段画不出、为布局美观需要删事实、未知关系要补默认含义、线型含义有争议。

可复制指令：

> 执行 T02。先把一份人工 Memory 正控稳定画为 SVG/PNG，交首件视觉证据，再扩全部符号和布局案例。只能按合同语义表表达，禁止依据原图或领域知识补画。拥挤时调整布局或报告容量/不支持，不能静默省略。交付图片、审计和实际验证结果；语义不明确交强模型裁决。

## 8. T03：完整页面路径

**性质：体力；评价标签和产品结论不可自行重定义。**

前置：共享 fixture；API 未完成也可实现可切换的数据访问层。真实 mode 未接通前明确展示 mock。

拥有：`src/app/page.tsx`、`src/app/layout.tsx`、`src/app/globals.css`、`src/components/`；不修改 `src/app/api/`、pipeline/storage、schema 和锁文件。

交付：上传/示例、3–5关键点与归一化确认、真实阶段状态、原图/重建图/事实笔记/逐条报告、可用 bbox 关联、失败状态、修改版对比、JSON/Markdown 下载入口和 replay 标签。英文产品文本方便比赛展示，开发说明用中文。

验收：使用同一 fixture 覆盖成功、unknown、无定位、超时、部分渲染、配置不匹配、mock/replay；现场演示无需打开开发者工具。默认页面不泄露目录路径或保留集答案。

可复制指令：

> 执行 T03。按总纲的用户路径和共享 fixture 做完整页面，优先让用户看懂“作者意思、A 理解、重建后 B 理解、差异证据”。把上传、等待、失败、未知、对比不一致和回放状态都做完。不得造综合分、假成功或伪实时结果；没有可靠 bbox 就显示条目证据。不要增加登录、数据库、网站部署或额外主功能。

## 9. T05：样例制作与数据整理

**性质：按配方制图是体力；标准答案、科学含义、改动是否单因素由 T04/玉米审核。**

前置：T04-D 标注规则、已批准的第一对语义配方、split。

拥有：`data/examples/`、`data/manifests/`、必要的 `scripts/examples/`。不修改 renderer、prompt、evaluator；不在 handoff 大量传播 holdout 真值。

交付顺序：1 对 dev 首件→T04 审核→最低 3 对（2 dev+1 holdout）→目标 6 对（4 dev+2 holdout）。每图附完整语义、3–5 K、来源/许可、版本改变、预期影响（假设）、审核状态。优先抽象图；正式演示补经核对的材料/化学语境。

问题版只改变可见清晰度/排布/图例对应等单一因素，不改变语义；关系真值变化的图另标 intent-mismatch 测试，不能混入清晰度成对对照。不要自选多次模型失败后最“漂亮”的例子再伪称预注册测试。

验收：每条 gold 能对应可见图元；每对语义答案相同且只改批准因素；同基础图所有版本同 split；源文件、渲染图、标注和 manifest 相互引用正确。每批由 T04 审核真值后才接模型。

可复制指令：

> 执行 T05。依已批准语义配方制作第一对自绘图并整理完整标注，交首件审核后再扩批。你的目标是积累可控、可追溯样例，不是用模型猜测生成标准答案。不要改科学含义、K、split 或标注口径；发现图元与真值不一致时报告 T04。保留各版文件，记录来源和许可，不覆盖旧版。

## 10. T06：集成与关键审查

**性质：脑力；建议延续 T00 的强模型上下文。**

前置：各模块至少首件可用。G0 后接管根配置、schema 变更协调；大改先交玉米。

拥有：`src/lib/pipeline/`、`src/lib/storage/`、`src/app/api/`、集成测试、根配置与脚本、`docs/MASTER_PLAN.md` 状态；跨模块修复先协调原负责人，防止双写。

交付：首条真实闭环、本地不可变记录、合法状态机、故障保留和重启 interrupted、资产访问、比较/导出、无隐私泄漏。审查 T01 请求、T02 像素输出、T04 判定、T05 gold；不能只看类型检查通过。

验收：按 VALIDATION 的 G1–G4 给出证据；至少一对真实图跑通且能说明每条差异来自哪段观察。复核 direct-check 未污染主链路。确认公开材料只包含允许分享的图。

可复制指令：

> 执行 T06，负责把已验收模块集成为可运行成品并做系统审查。先完成一个真实 run，再扩批；逐段检查输入隔离、绘图忠实、判定依据、版本可比性、错误/回放标识。不要为了集成而降低合同或手写模型输出。对阻断缺陷给根因与最小修复，将状态和剩余风险写入指挥台，提供可重现启动与演示步骤。

## 11. T07：批量验证、证据和提交草稿

**性质：体力长跑；统计口径、因果解释与最终主张交 T04/T06/玉米。**

前置：G2、冻结版本、批准批次清单；真实 API 批次需已有权限与资源上限。可先整理非付费 fixture 报告和材料框架。

拥有：`scripts/validation/`、`docs/handoffs/T07-validation.md`、`artifacts/validation/`、`docs/submission/`。真实结果仍写 `runs/`，不可覆盖旧 run；不改业务代码、prompt、gold 或测试期望。

交付：逐图结果、流程失败分母、重复运行波动、A-only/direct-check 对照、渲染正控截图、配置摘要；2分钟核心视频脚本、≤4分钟完整脚本、一页英文说明、提交检查表。生成 PDF/视频等成品时按对应技能工作流，不在纯 Markdown 阶段引入额外工具。

验收：数据和报告能按 run ID 回查；没有把无效运行丢掉刷通过率；失败/重试/人工介入透明；结论不超证据；帖子与表单仅草稿，不实际发布。

可复制指令：

> 执行 T07。按冻结版本和批准清单持续完成有限批次的验证、取证和提交草稿。每个样例执行后保存 run ID、配置、成功/失败、用量和报告位置；每批写检查点，任务中断后可接着做未完成项。不要边跑边改 prompt、阈值、gold 或模型；异常交脑力负责人审查。完成后分别汇总流程失败、有效结果和不确定项，不能编造提升或选择性隐藏失败。不要发帖、部署、push 或正式提交。

## 12. 长跑协议

每个体力任务首件验收后才扩大批次。批次清单至少记录 `item_id / input_version / config_digest / status / output_ref / attempt / cost_usage / blocker`。

1. **有终点**：本批做哪些图、版本、页面状态、运行；做完即停。新样例是有价值积量，反复跑已通过且未改动的同一检查没有收益。
2. **有资源边界**：设置最大任务数、调用数、单次超时与已批准费用上限。达到任一上限停付费分支并汇报；无额度不无限跑。
3. **有检查点**：每完成 1 个图对或最多 30 分钟更新任务 handoff；真正无消息进展时也记录当前阻断，便于换模型接手。与用户的实时沟通仍遵守会话更新要求。
4. **可续跑**：根据清单只做未完成项；不能因进程重启把已完成 run 当新实验重跑、重复计数。
5. **有限重试**：按合同最多 2 次临时故障重试；同类根因连续出现 3 项、schema/prompt 不一致、语义映射有疑问时暂停受影响批次并升级。
6. **不可偷改**：不通过改变意图、扩大匹配、删除难例、切模型或补写答案来完成指标；所有改动先经脑力负责人批准并形成新版本。
7. **可审核**：每批交付事实表与证据，让强模型作抽查/必要全查；样例真值和科学含义仍须逐项审核，不能只抽外观。
